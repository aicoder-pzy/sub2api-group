# 分组模型调度

在「账号管理」先筛选分组，再打开「模型调度」。每个分组独立保存精确模型名及允许调用的账号，弹窗仅列出该分组的账号。

规则仅限制当前调度分组：同一模型可以在不同分组使用不同白名单；没有配置该模型时沿用该分组正常调度；配置空账号列表时拒绝该分组的该模型请求。删除规则只解除当前分组的限制。

普通请求、最快故障切换、已有会话绑定、Responses 续接、WS 后续轮次、分组鹈鹕测试及自动评测的评委分组均应用对应分组的规则。规则使用公开请求模型名，先于渠道和账号模型映射。倍率上限等原有资格检查仍适用。

管理员 GET/PUT `/api/v1/admin/settings/model-account-routing` 必须带正整数 `group_id` 查询参数，正文仍为 `{"rules":[{"model":"gpt-6.1-sol","account_ids":[134,135]}]}`。设置存于 `model_account_routing_group_<分组ID>`，各组更新和缓存相互独立。读取失败仅拒绝对应分组的调度。

迁移 `249_custom_group_model_account_routing.sql` 按旧白名单账号当前所属分组拆分规则，只保留各组内的账号。旧空白名单在所有已有分组保留拒绝规则；非空列表没有账号绑定的分组不再受到旧全局规则限制。已有分组规则不会被覆盖。原 `model_account_routing` 保留用于回滚，新版本不再读取它；回滚后的旧程序使用这份迁移前的全局快照。
