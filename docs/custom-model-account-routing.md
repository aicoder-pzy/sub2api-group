# 全局模型账号白名单

后台「账号管理」工具栏的「模型调度」配置每个具体模型允许调用的账号。
可以先勾选账号，再新增模型，勾选账号会成为新规则的初始白名单。
账号搜索覆盖全部账号，独立于账号表格的分组、平台筛选和分页。

- 模型 ID 精确匹配客户端请求的公开模型名，不支持通配符。
- 未配置规则的模型沿用原调度；删除规则会解除该模型的限制。
- 已配置规则的模型只能使用白名单内账号。空白名单明确禁止该模型调用。
- 分组成员关系、平台和模型支持、状态、配额、并发、优先级、权重仍生效。
- 会话粘性、previous_response_id、最快故障切换及代理熔断回退不能绕过白名单。
- 白名单全部不可用时返回原有无可用账号错误，通常是 HTTP 503。
- WebSocket 每轮请求复查白名单；当前连接的账号不再允许时要求重连。
- 删除账号不会自动删除白名单规则或放宽限制；遗留 ID 仍显示为 #ID。
- 白名单不会改变实际转发模型，也不会赋予账号上游模型权限。

持久化复用 `settings` 表，不新增数据库迁移。管理员接口：

```http
GET /api/v1/admin/settings/model-account-routing
PUT /api/v1/admin/settings/model-account-routing
```

```json
{"rules":[{"model":"gpt-6-astra","account_ids":[118]},{"model":"gpt-6.1-sol","account_ids":[118,128]}]}
```

保存成功立即更新当前进程缓存；其他实例最多 5 秒内更新。
缓存到期后若读取或解析配置失败，会拒绝调度，不会将白名单视为未配置。
已开始的上游请求不会被撤回。管理员单账号测试仍可用于检查白名单之外的账号。
