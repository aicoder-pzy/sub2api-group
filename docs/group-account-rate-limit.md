# 分组账号倍率上限保护

在「分组管理 → 新建/编辑分组」启用「账号倍率上限保护」，填写上限。默认关闭，初始上限为 0.21。账号当前倍率必须**小于或等于**上限；0.21 上限允许 0.20 和 0.21，排除 0.22。支持 OpenAI、Anthropic、Gemini、Grok 和 Antigravity 的 token 调度，包含最快故障切换、优先级及会话绑定路径。

优先采用上游 `/v1/sub2api/billing` 探测声明的当前实际倍率，实时计算声明中的高峰时段系数。不支持探测或尚未取得声明的账号采用手工成本倍率。已有声明失败但仍有效时继续使用；声明失效或无法解析时暂停选号，等有效探测结果恢复，避免用较低的手工值错误解冻。此开关不修改账号的手工成本倍率、销售倍率或利润控制配置。

暂停仅作用于开启保护的分组，不改账号全局状态或手工禁用开关。保护分组中的 API Key 账号自动加入现有定时倍率探测，即使账号自己的探测开关未打开；仍遵循「上游倍率探测」全局开关与探测间隔，当前站点配置为 30 分钟。没有额外模型生成请求。倍率合格后自动恢复资格，手工暂停的账号仍保持暂停。

每次选号、等待并发结束和发送前复核倍率。会话不能通过旧绑定继续使用已超限账号；当前已提交的请求允许完成，下一条请求切换。原生 WS 连接会在下一轮请求前复核，超限时关闭连接并要求客户端重连后重新选号。HTTP 转 WS 请求由 HTTP 请求的正常换号流程处理。

上游未公开的临时改价需等待下一次探测才能发现；已声明的高峰边界按当前时间立即判断。全部账号超限或倍率未知时返回无可用账号，不越过上限兜底。管理员「刷新调度」可查看当前倍率、包含等于的上限及冻结原因。
