# custom：BPS、票据探针与代理池

管理入口：**BPS / 票据探针**（`/admin/bps-tickets`）。配置按账号和模型生效，不绑定分组，不替换 custom 现有的分组评测、首输出超时、粘性调度与计费机制。

## 来源与维护

本次选择性迁移自 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api/tree/5ca3cca21eeaf4ca8a694a7f2f8f0ecd9575c549)，固定版本 `5ca3cca21eeaf4ca8a694a7f2f8f0ecd9575c549`（production / v2.10.0）。复用了 `basispoints` 协议包、Mihomo 管理与代理池、票据状态探针、780 路由 Cookie 校验；全局设置、后台任务和现有网关的连接代码在 custom 内实现。

源仓库与本仓库均保留根目录 LGPL-3.0 许可证。BPS 协议包的上游作者、MIT 来源和后续参考说明保留在 [NOTICE.md](../backend/internal/service/basispoints/NOTICE.md)。未将源仓库的独立调度、支付、用户管理等改动整体合入。

`origin` 仍指向 aicoder-pzy/sub2api-group，`upstream` 仍指向 Wei-Shaw/sub2api。后续官方升级继续按现有方式合并到 custom；本功能是独立提交，不改变官方追踪链。

## 使用

### BPS OAuth 授权

授权入口选择性迁移自 [PR #343](https://github.com/ranxi2001/sub2api/pull/343)，固定提交 `46b4bc50caf2694a661764004a7a9233eb6376ed`。未迁入密码 / TOTP 自动授权 worker。

1. 打开“账号管理 → 添加账号 → OpenAI → BPS OAuth”，填写名称、代理和需要走 BPS 的模型。
2. 生成授权链接，通过官方 Excel 登录。授权后复制地址栏包含 `code` 和 `state` 的完整回调 URL，回到管理页面完成授权。不要分享回调 URL。
3. 新账号使用独立 Excel OAuth 会话，所选模型立即启用现有 BPS 转发；不会自动开启定时探针、采票或修改其他账号。
4. 后续在“BPS / 票据探针”修改模型和代理来源。重新授权会继续使用 Excel 客户端，并保留账号配置。

也可使用 Excel 会话配套的 Refresh Token，或在普通 OAuth 入口导入会话 JSON。JSON 必须保留原 `client_id`，以及配套的 `access_token`、`refresh_token`、有效期和账号 ID；不同客户端独立建号。JSON 导入后需在“BPS / 票据探针”启用所需模型。

旧 Codex RT 不能通过修改 `client_id` 转换为 Excel 会话。Excel 刷新使用官方 `unified=true` 端点，不携带 Codex 的 scope 或身份头。部署验证只覆盖本地模拟授权和线上授权链接生成，真实登录由管理员完成。

参考仓库在少量账号上验证了 Excel 授权可避开旧 Codex 凭据的 BPS 403，但其 Astra 请求曾返回声明为 `gpt-5.6-luna` 的响应。因此，授权成功不代表所有账号均可用，也不保证真实模型或解决降智。

### 票据配置

1. 在“全局配置”设置采票格式、频率、预算、探针间隔和连续结果阈值。后台采票与定时探针默认关闭。
2. 在“账号与状态”填入该账号支持的模型名称，选择 BPS、采票、定时探针和自动切换，保存账号设置。账号模型映射仍生效。
3. “手动票据探针”检查原生 Codex 通道，不修改路由；“立即采票”执行一次有次数上限的采集；“测试转发”使用现有账号测试，按已保存的 BPS 配置转发。操作会产生上游请求与额度消耗。
4. 开启所需的全局后台开关后，任务只处理 active、可调度且明确勾选该功能的账号。暂停调度账号不会被后台主动请求。

BPS 适用于非影子的 OpenAI OAuth 订阅账号，不支持 Free、Agent Identity 或个人访问令牌。支持 Responses 文本、客户端 function/custom 工具、聊天/Anthropic 兼容接口，以及 Responses 中的 HTTPS 图片、文件引用和有上限的内联图片上传。显式会话的工具目录按 API Key、账号凭证与会话隔离；无明确会话时要求完整工具声明。

BPS 请求使用自己的鉴权和协议头，不带 Codex 票据、路由 Cookie，也不交给 Codex OAuth 插件。BPS 不支持的原生端点（如 compact）、不透明加密历史或托管工具会明确报错，不静默删掉上下文或转回原生模型。本次没有接入独立的 BPS `/images/generations`、`/images/edits` 入口或源项目的图片公网中转服务。

启用这些功能的账号，其 WebSocket 入站通过现有 HTTP bridge 转发，采票和票据使用统一走 SSE 上游，避免在 SSE 与上游 WebSocket 之间混用票据。

## 探针与自动切换

探针执行两次短请求：首次不带票据和 Cookie，第二次带首次返回的票据及路由 Cookie。两次均须 HTTP 200、流完整结束，并且路由未改变。

- **未见异常**：续接未返回不同票据。
- **疑似异常**：续接返回另一张有效的 780 票据。
- **无法判断**：292/332 或其他票型、票据过期、Cookie 无效、路由改变、超时、限流、流不完整等。

这是一条票据变化的经验判据，**不能证明真实模型名称或智力变化**。响应中声称的模型名也不作为能力证明。

自动切换按模型分别计算连续结果，默认连续两次疑似异常后启用自动 BPS，连续两次未见异常后撤销自动 BPS。无法判断会中断连续计数，但不改变当前自动路由。自动恢复不会关闭手动 BPS。修改账号配置、模型映射或凭证会使旧自动状态失效，避免旧检测覆盖新配置。

关闭全局定时探针仅停止后续检测；已生效的自动 BPS 保留。若要立即撤销，关闭该账号的“自动切 BPS”并保存。手动 BPS 仍由手动开关控制。

## 780 / 292 边界

- 780：校验票据的结构、签发时间、完整 Cookie 对、Cookie 有效期和目标网关。有效期最多 240 秒，不对 Lite 请求注入。
- 292：使用 Lite 请求采集；Team/Business/Enterprise 计划按 332 长度校验，不把它们当作坏票。
- 292/332 可用于采票与转发，但不用于上述“疑似异常”判据。
- 票据绑定账号凭证、模型和采票出口。改账号、换凭证、票据过期、代理被禁用/修改或网关不匹配时，不复用旧票据。
- 默认不拒绝无票流量；开启“缺少有效票据时拒绝”后，返回可切换账号的 503，由现有调度继续处理。

票据只存于应用进程内存，不写入日志、管理 API 或账号导出。重启后重新采集；自动检测结果与配置存于已有 settings / accounts.extra，无新增数据库迁移。当前后台任务和票据缓存面向现有单实例部署；多副本部署需要先增加共享票据存储与分布式任务租约。

## 代理池

- **账号原代理**：使用该账号原有代理；未配置代理的账号使用直连。
- **静态代理池**：复用“代理管理”中的 HTTP/SOCKS 代理，在全局配置选择成员。排除停用、过期成员；BPS 预热后使用，采票按成员轮换。
- **Mihomo**：Linux amd64/arm64 上支持内核安装、订阅增删/更新/停用、动态代理、地区筛选、节点恢复、单次采集退休与 BPS 预热池。订阅凭证不回显。采票与转发使用租约固定节点，节点不可用时不偷偷改出口。

选定的 BPS/采集代理池为空时不回退直连。全局“缺票拒绝”关闭时，普通业务仍可按原有账号出口进行不带票据的原生转发。

Mihomo 配置与内核位于 `DATA_DIR/mihomo`，需要持久化现有 DATA_DIR。内核管理只支持 Linux；Windows 可开发/编译协议和控制界面。Mihomo 的 shell/权限测试应在 Linux 上运行。

## 发布与回滚

迁移合入 custom 后，由现有 GitHub Actions 构建 `ghcr.io/aicoder-pzy/sub2api-group:custom` 和固定提交镜像。发布镜像不等于重启生产服务器。

上线时先保持后台开关关闭，用一个账号、一种模型验证 BPS 文本、工具与计费，再开启选定账号的定时任务。需要回退时使用此前固定提交镜像；本功能没有数据库结构变更，原镜像会忽略新增设置。
