# IP 风控与 ModelTrace 指纹测试

本次选择性接入 [ranxi2001/sub2api v2.17.3](https://github.com/ranxi2001/sub2api/tree/e6368c48fd253266608cdb85e15e8725cdfad955) 的 IP 风控（#487、#501、#513、#566 中相关部分）和 ModelTrace（#467）。保留本站模型映射、分组调度、测智计划、钱包及通知实现。

## IP 风控

- 入口：管理员侧栏 **IP 风控**，地址 `/admin/ip-risk`；系统设置的安全页也提供入口。
- 配置保存在现有 settings 表的 `ip_risk_control_v1`，不增加数据库迁移。新安装默认关闭、预选观察模式；生产接入先观察，再由管理员按实际事件调整阈值和启用拦截。
- 支持 IPv4/IPv6/CIDR 白名单、可过期黑名单、登录/注册/验证频率、明确凭证失败计数、临时封禁、国家准入、认证入口 UA 规则。白名单优先，模型 SDK 不受认证入口 UA 规则影响。
- 国家查询仅在配置国家规则时执行，由服务端向 GeoJS 查询可信客户端公网 IP，Redis 缓存；不使用客户端提交的国家声明。
- 计数、自动封禁、有限事件记录存入共享 Redis；事件最多 2000 条，按配置保留期清理，支持筛选分页、清空、解封及策略预览。
- 保存前检查当前管理员是否会被配置直接锁出。风控依据显式 `server.trusted_proxies` 解析 IP，不使用兼容开关放行的任意转发头；反向代理部署必须准确维护可信代理范围。
- 独立的匿名 API 防护默认关闭；启用后仅在已确认凭证无效的请求上检查共享封禁，同一 NAT 下有效 Key 仍可访问。可选成功清理只清匿名计数，不移除静态黑名单。
- `IP_RISK_DISABLED=true` 为进程启动时的应急旁路；Docker 部署须把该变量传入容器并重建应用容器，修正规则后移除。此开关不关闭既有鉴权或其他防护。
- 全局风控关闭后新请求旁路；各节点约每 5 秒刷新配置。初次配置加载失败保持关闭，之后失败保留最后有效配置。动态存储失败时认证风控可返回 503；普通业务仍检查静态可判定规则。

## 指纹测试

- 入口：账号管理 → **智商测试 → ModelTrace 指纹**。
- 手动选择模型及思考强度，每轮固定同一账号依次发出三道独立随机数字题；每题最多 240 秒，可停止，取消后不启动后续题，不自动补题。
- 复用本站原生 OpenAI Responses/Chat Completions 和 Anthropic Messages 测试链路、模型映射、代理及存储的账号凭据；不接受外部 URL 或凭据。特殊 BPS、影子、服务账号等通道明确拒绝，OAuth 必需系统指令保留并显示。
- 内置固定版本 ModelTrace 算法和约 0.93 MB 指纹库，不增加 Python 服务、在线评分服务或运行时下载。来源提交、库 SHA256 和 MIT 版权保留在 `backend/internal/pkg/modeltrace/`。
- 拒答、截断、异常 EOF、超时或数字不足不参与汇总；只有 1–2 份有效结果标为初步归因，无有效结果不生成概率。显示逐题结果、映射模型、候选模型/家族概率及分歧。
- 每轮最多消耗三次真实上游额度；只有管理员点击开始才执行。历史只在当前浏览器按账号保存最近五轮，不保存 Key 或提供方错误正文。
- 概率是候选库中的相对归因，不能证明模型身份或降智；测试结果不触发本站自动隔离、切号或质量评分写入。

验证：所有编译、动态回归、前端类型检查和生产镜像构建交由 GitHub Linux CI；本地只进行源码编辑和格式检查。生产验收不主动调用收费模型。
