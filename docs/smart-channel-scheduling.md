# 智能渠道调度

在「分组管理 → 新建/编辑分组 → 账号调度方式」选择「智能渠道调度」。这是一个统一模式，内部按模型能力、质量、可靠性、速度、容量和成本完成主备选择、真实会话试用、故障接管与恢复。模式值为 `smart_channel`。

## 模型能力与准入

同组成员不必支持相同模型。每个请求先应用 Key 映射和分组准入，再在该服务模型允许的渠道内调度，最后沿用渠道/账号上游模型映射。不会默认跨模型降级。

该模式需要明确的模型声明，来源按以下顺序判断：

1. 本组「账号管理 → 模型调度」中该模型的精确渠道范围。空范围继续表示拒绝该模型，其他声明不能绕过此限制。
2. 账号模型映射中的精确或通配匹配。
3. 已同步并持久化的上游模型元数据目录。

空映射和透传不构成“支持所有模型”的声明。模型目录是供应商声明，不是成功调用或真实模型身份的证明；现有模型级限流、近期质量、额度、倍率、利润、协议能力和发送前终检继续生效。同步失败不清空已保存声明。普通旧模式保留原有空映射语义。

首选使用分组精确模型规则列出已确认渠道。例如 `gpt-6.1-sol → [A,C]`、`gpt-6-astra → [A,B]`。普通请求、重试、会话绑定、previous_response_id 和 WebSocket 后续轮次均受同一范围限制。

## 排名、会话与升级

复用模型自动优选：先比较质量、完整响应可靠性与近期故障，再比较同思考强度、公共上下文档位的 P50/P95、输出速度和实际单位成本。没有足够证据时稳定兜底，不把未知显示为 100% 或质量正常。

健康会话继续使用原渠道。备用只有最近 24 小时内存在正常质量结论、没有待确认降智，且最近测智的思考强度与当前请求强度一致（未指定时按现有证据选定强度）时，才参与主动试用。未知、过期或强度不匹配的渠道保留故障兜底资格，不为凑证据自动发起检测。

首次合格备用可接收一个自然产生的新会话；之后两次试用分配之间必须同时满足至少十次新会话分配、至少三十分钟冷却。分组与模型隔离，Redis 原子执行，多个实例、并发与重试共用额度；仅实际获准的试用推进备用轮转。已有健康会话不计数，不迁移、不复制请求，不新增自动付费探测。限制的是新试用会话数，不是后续对话的请求量或 token 费用；没有会话标识时不主动试用。旧 `model_auto` 模式保留原每十个新会话一次的策略。

升级至少需要双方各二十条同强度、可比较上下文样本，连续三次间隔五分钟的优势确认和三十分钟主用保持期。沿用现有质量、可靠性、P95、输出速度和成本优势阈值。升级候选在新会话完整成功后通过 Redis CAS 提交；旧请求晚完成不能覆盖新绑定。

速度比较将缓存 token 计入上下文，档位为 <8K、8K–32K、32K–128K、128K–200K、200K–256K、≥256K（K=1024），避免把所有长上下文混在一起。关联异常同时识别服务端请求 ID 与 `client:` 请求 ID，隔离分组和 API Key；排除该渠道出现错误的样本，保留另一渠道成功接管的样本。可靠性与渠道统计使用相同客户端标识口径。现有用量首输出和耗时仍按单次转发计量，不能解释为含此前重试的全程等待。

首次降智保留服务，五分钟后固定原渠道复测；仍降智才进入替换处理。失败/未知不能确认降智。迁移 257 将现有数据库触发器和复测工作列表扩展到该模式，不创建或启用任何检测计划。

手动、定时和确认复测均携带公共模型上下文，复合分组改写上游模型后仍按公共模型执行准入终检。此修复不新增检测计划，也不提高既有检测频率。

正式主用渠道切换后，独立后台每十秒检查最近一小时的已提交切换；初次绑定、备用自然会话试用和临时容量分流不触发。仅复用当前启用且在运行时段内的既有测智计划，沿用其问题和思考强度，补一个样本，不改变 cron、下次例行执行时间、启用状态或配置的并发样本数。没有对应计划时不自动创建。

同分组（或无分组的账号测试）、同渠道、路由模型和测试强度最近一小时有正常或降智结论时复用结果；最近五分钟有失败或未知记录，以及相同模型计划正在执行时暂不补测。补测使用现有计划租约和 Redis 原子预约，多实例、重复切换及切回同渠道共用一小时冷却；失败也保留冷却。每分组、公共模型的切换补测数量另按当前 `degradation_tests_per_hour` 的数值设滚动小时上限，与原降智确认预算分别计数，未修改该配置。后台最多同时运行四个切换补测。

补测只测试新主用渠道，仍执行模型能力、分组规则和并发槽后的最新状态检查，不在失败时改测其他渠道，不提交主用绑定。若执行前该计划已编辑、停用，或目标已非当前主用，则跳过；常规测智和原降智确认流程继续按各自规则执行。

智能模式原有的降智替换后测智也共用上述一小时证据、冷却和补测预算，避免与后台切换补测重复消耗；固定原渠道的五分钟降智确认仍按原规则执行。

## 容量分流与故障接管

主选渠道满载时，使用现有 Redis 等待计数短暂等待，整条逻辑请求最多进行一次两秒的容量等待。之后尝试其他合格渠道的空闲槽位。所有渠道满载时返回原主选渠道的既有有界等待计划，继续遵循等待队列上限和客户端取消。

容量备用成功不改变分组主用，也不覆盖健康会话的旧粘性绑定。上游故障仍沿用最多一次同渠道重试、跨渠道共享发送时间预算和成功后提交规则。真实故障备用完整成功可以接管主用。输出开始后不能拼接另一个渠道的回答。previous_response_id 等供应商私有上下文继续走现有绑定/传输检查，不保证跨供应商续接。

## 中转错误隔离

适配参考仓库 [#500](https://github.com/ranxi2001/sub2api/pull/500)、[#545](https://github.com/ranxi2001/sub2api/pull/545)、[#515](https://github.com/ranxi2001/sub2api/pull/515) 的边界修复：

- 明确的上游会话封锁、内容策略 403 和确切的内部 WS 握手 403 不进入账号自定义处罚、403 累计和运行时整号阻断。
- 会话封锁与内容策略拒绝返回当前请求错误，保留客户端可用的提示；不会借此新增本地 cyber-policy 命中。
- 普通 OpenAI API Key 的 429 使用现有兜底冷却配置，避免持久化供应商内部 Codex 周限额或 plan_type。管理员连接测试同样不写入这些长期状态。
- 智能模式的池渠道也执行短暂 429 退避和模型不存在处理；普通中转 Key 不按透传的个人 Codex 使用率自动停调。明确供应商专用配额和管理员规则仍按原入口处理。
- 真实认证错误及其他未命中结构化条件的错误保留既有处理。升级不自动清理历史冷却或旧计数。

以上新识别针对 HTTP 错误体；WebSocket/SSE 帧内错误继续走现有帧分类，不能将此次范围解释为新增了全部帧级策略识别。

## 查看、发布与回退

2026-10-27 修复：调度缓存保留 `openai_capabilities`，使候选与完整账号使用一致的端点能力。`gpt-6.1-sol` 的 Responses 工具请求遇到仅支持 Chat 的账号时，发送前允许既有有界循环选择兼容账号，不先写出 400、不处罚账号健康、不删除工具或修改模型。私有上下文与输出后禁止重放限制仍有效。选择性适配官方未合并 PR [#7761](https://github.com/Wei-Shaw/sub2api/pull/7761)、[#8295](https://github.com/Wei-Shaw/sub2api/pull/8295) 及相关回归。

分组测智采购估算复用现有定价和账号统计规则，再乘账号 `rate_multiplier`；未设倍率沿用正式统计的 1，零倍率有效。不再使用 `extra.cost_multiplier` 或静默默认 0.1，历史金额不回写。迁移 `258_custom_pelican_cost_details.sql` 为新结果保存每次尝试的用量、模型、档位、强度、倍率、价格快照及哈希、费用和不完整标记，包括有用量的失败尝试。缺失证据时标为未记录或部分。费用提示可查看渠道倍率；该金额仍是估算，不是供应商扣款回执。例行计划和测智间隔不变。

中转过载判定选择性参考已合并 [#569](https://github.com/ranxi2001/sub2api/pull/569)。HTTP 与共享流内容量判定保留认证、权限、配额和安全错误的优先级；结构化 JSON 不扫描回显的用户内容。明确容量耗尽跨中转保留 `upstream_capacity_exhausted`，耗尽既有重试预算后返回 503。默认容量信号不写整号冷却，管理员显式规则继续优先。

智能模式普通 OpenAI 兼容 API Key 的模型不存在保护缩短为映射模型维度的 30 秒，不修改模型声明。自定义错误码、显式临时处罚和真实 OAuth 模型能力错误沿用原规则。旧模式默认池不再由 fastpath 绕过池策略写模型负缓存。透传模型不存在也能在写出前尝试其他渠道。共享发送预算、同号重试上限及输出后不重放保持原语义，不自动清理历史冷却。

「调度状态」只读展示模型声明渠道数、当前合格数、声明来源、上游模型名、主备排名、冷却/排除原因、质量证据、同强度速度、单位成本及自动升级进度。打开此视图不会发起付费模型请求或改变评估/绑定。声明渠道数不等于当前可服务数量；少于两条合格渠道会提示缺少备用。

发布不会自动改变任何分组的模式。启用前查看所需模型的调度状态并补齐声明。其他配置、Key 映射、凭据、计划与绑定继续沿用。

回退旧二进制前，将已启用智能模式的分组改回之前保存的模式。迁移 257 仅扩展复测触发器，无删除性数据变更；保留迁移与历史数据。旧二进制不认识 `smart_channel`，不能直接带着该配置回退。

构建、单元/集成测试、前端和 lint 通过 GitHub Linux CI 执行。本机仅进行源码修改、格式化和静态差异检查。
