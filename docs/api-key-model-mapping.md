# API Key 模型映射

用户在「API 密钥」创建或编辑窗口添加「请求模型名 → 实际模型名」。管理员在「用户 → API 密钥 → 模型映射」管理任意用户的 Key。

例如 `my-model → gpt-6.1-sol`，客户端使用该 Key 请求 `my-model`，网关按 `gpt-6.1-sol` 执行分组准入、路由、渠道选择和计费。目标模型仍受分组权限与现有渠道规则约束；这项功能不增加模型权限。

- 只影响配置的 Key；未命中规则的模型照常处理。
- 精确、区分大小写、只匹配一次，不支持通配符或递归映射。
- 最多 100 条，模型名最多 256 字节。空值、空白、控制字符和通配符不允许。
- API 字段 `model_mapping` 为字符串对象；更新时省略或 `null` 保留原值，`{}` 清空规则。
- HTTP 请求在认证后、分组白名单和合成路由之前映射；支持 JSON、multipart 上传、Gemini 模型路径和 Realtime 查询参数。
- Responses WebSocket 首帧及后续帧均使用连接建立时的规则。修改后重新连接。
- 调度、计费、日志及响应模型名使用映射后的模型，再沿用已有分组、渠道和账号映射规则。
- 模型发现列表仍使用现有分组目录；自定义别名可以直接作为请求的 `model`。

数据库新增可空 JSONB 列 `api_keys.model_mapping`，旧 Key 默认无映射。回退应用保留该列和当前数据，无需恢复旧数据库。
