# 分组质量、倍率与优先调度（v0.2.13 定制）

分组选择“最快账号故障切换”后，按分组和请求模型独立保存当前账号。

调度规则由 `fastest_failover` 模式统一控制，不依赖分组名称、固定分组 ID、账号 ID 或供应商。
分组只决定候选账号与模型绑定；超时策略共用，模型冷却属于账号状态，同账号在其他分组也受影响。

## 全局配置与主动更新调度（2026-10-07）

“系统设置 → 网关 → 最快故障切换 · 全局配置”可设置首输出超时（1–600 秒）、
流空闲超时（1–1800 秒）及模型冷却（1–86400 秒）。默认仍为 60 / 120 / 120 秒，
下文的固定秒数指默认值。配置保存在 settings 表，无新增迁移；保存后当前实例的后续转发尝试立即使用新值，
其他实例最多 30 秒同步。每次转发尝试使用固定快照，修改不会重置正在执行的计时器或已存在的冷却期限。
缓存刷新失败时沿用上次有效配置。配置作用于所有启用该模式的分组，传输接入范围见下一节。

账号管理页先按一个启用该模式的分组筛选，再点击“批量更新”左侧的“更新调度”：

1. 选择或输入一个具体文本模型；打开窗口只加载候选模型，点击“开始评测并更新”才调用上游。
2. 后端读取整个分组，逐个评估，不受分页、其他搜索条件或勾选账号影响。可用性、模型映射、平台、配额、路由和并发检查仍生效，不可用账号显示跳过。
3. 使用现有账号连接测试请求，实际产生上游费用。记录首个非空文本输出的耗时，空响应、异常、超时或未完成的响应视为失败；最长测试时间为首输出超时加流空闲超时。结果通过 SSE 实时显示。
4. 本次成功结果用于重新选择，忽略旧绑定及历史质量缓存；保留人工优先调度及其优先级，同级优先账号按实测耗时排序。普通账号在本次最快耗时的 1.2 倍内优先选择低倍率账号。
5. 重新检查账号和分组后，仅写入此模型的绑定。存在可用成功账号时，对测试失败账号的此模型应用全局冷却，避免失败的优先账号立即抢回绑定；模型冷却仍为账号级状态，其他分组共享该账号时也会避开它。原测试服务的认证异常、限流等状态维护仍生效。
6. 关闭窗口会取消未完成的测试。取消、全部失败、最终无可用账号或绑定写入失败不会由此操作替换旧绑定。若断网恰好发生在最终写入之后，界面可能收不到完成事件，可刷新列表确认。

每个服务进程同一分组只允许一个评测任务；多实例部署应避免同时对同组发起评测。
评测只更新绑定，不改账号优先级，不写入客户用量账单；单次短请求不是长期质量保证，日常自动选择仍使用原历史统计规则。

## 优先调度缓存修复（fastest.6）

- 公共调度精简快照保留 `scheduling_preferred`，修复完整账号已开启优先调度、但候选排序看不到开关而继续使用旧绑定的问题；适用于所有使用此快照的账号平台和分组。
- 只有分组启用“最快账号故障切换”才按该开关优先选取，默认调度模式不变；模型不支持、暂停、限流、冷却等条件仍然优先检查。低倍率本身不抢占仍可用的绑定。
- 发布时由应用启动的全量调度快照重建更新现有缓存，随后核对数据库、完整缓存与精简缓存的优先标记；无需逐个重新开关，不清除模型绑定、不修改账号配置。接管发生在后续选号时，不中断已在执行的请求。
- 回归测试覆盖真实 Redis 缓存序列化及候选读取路径、十个平台、同账号多个分组、开关开启/关闭/缺省及重新开启，以及 OpenAI/Grok 的旧绑定接管和模型不支持时排除。

## 超时故障切换（fastest.5；2026-10-07 补齐 Anthropic 接入）

- OpenAI HTTP Responses（含透传）、Chat Completions 与 Anthropic HTTP 转发共用同一套超时及模型冷却实现。Anthropic 覆盖 Messages 普通转发、API Key 透传、Bedrock，以及 Chat Completions/Responses 协议转换入口；普通调度模式保持原逻辑。
- 首个输出统一等待最多 60 秒，包含等待响应头和仅收到前导事件的时间，不因 high/xhigh 推理而延长；已经开始输出后，120 秒无上游数据判定超时。
- 首输出前的心跳、response.created、空 message_start、空文本/思考开场事件不会取消 60 秒期限。Anthropic 暂存这些开场事件，实际文本、思考、工具调用或正常终止事件到达后再一起发送；开场缓冲上限 1 MiB，只有开场便断流时允许换号。非流式请求（包括内部读取 SSE 后转为 JSON）在返回完整响应前也受 60 秒期限限制。
- 超时中止当前上游请求，按现有模型映射将该账号的该模型冷却 2 分钟，并同步调度缓存。冷却期内即使开启“优先调度”，也不能再次选中；其他模型不受该次冷却影响。模型冷却属于账号级可用状态，因此其他分组共享这个账号时也会避开它的同一模型。
- 尚未向客户端输出实际内容时，返回可切换的故障交由原重试循环选择新账号；次数仍受原故障切换上限限制，没有可用备用账号时返回错误，不无限重试。
- 已经输出内容时不重放当前请求，结束当前流并报告错误；客户端后续重连会避开冷却账号。客户端自行断网或取消不等同于上游超时，也不会据此主动发起重复请求。
- WebSocket、Gemini、Antigravity 专有转发和 Grok 独立转发路径尚未接入这套 60/120 秒保护，仍使用原有机制；公共调度模式并不代表所有传输路径均已接入超时。关闭调度开关不会主动中断在途请求。
- Anthropic 选号会重新检查账号当前的可用状态，避免旧快照重新选中仍在冷却的优先账号。已向客户端输出后发生超时，保留观测到的用量，并由原有字节检查禁止重放；首输出前换号沿用仅记录最终服务尝试的计费语义。
- 自动换号可能使已开始计算但尚未返回输出的请求产生重复上游费用。
- 60 秒是保留的现有阈值，不保证赶在超时仅约 31 秒的下游之前换号。若要满足更短的下游期限，应统一调整该模式的首输出阈值，并为备用账号响应留出时间，不能为某个分组写例外。

## 选号规则

选择流程：

1. 沿用平台、模型映射、端点、限流、配额、暂停、路由与账号状态等可用性检查。
2. 如果有可用账号开启“优先调度”，它优先于速度、统计质量和倍率排序；多个开启时按优先级数字从小到大选择，同级已有绑定继续使用。不支持当前模型、暂停、限流、失效等账号仍不参与。
3. 比较失败率，再在失败率距最佳账号不超过 2 个百分点的账号中找最快的 P95 延迟。流式使用首 Token 耗时，否则使用总耗时。速度候选范围为该最快值的 1.2 倍以内。
4. 没有优先账号且没有可用绑定时按上述统计质量形成候选，选择低倍率账号；倍率相同按原优先级、最后使用时间排序。
5. 选中后持续使用到不可用，满并发时排队。开启可用账号的“优先调度”或提高已开启账号的优先级，可以接管当前绑定。关闭开关不主动清除仍可用的绑定。

例如：A 和 B 均进入质量候选，B 倍率低，则选择 B。开启 A 的“优先调度”后切换到 A，即使 A 更慢、更贵；A 暂停或模型不支持时不会被强制选中。

账号管理页“优先级”列的“优先调度”开关默认关闭，仅作用于此分组模式。通过原有批量更新接口对单账号增量保存 `extra.scheduling_preferred`，不覆盖其他扩展字段。账号设置作用于该账号所在的所有使用此模式的分组。

倍率优先读取有效期内的上游计费探测值（包含动态时段倍率），否则使用账号计费倍率；未设置按 1 处理，0 倍有效。用于估算渠道成本，不改变用户计费规则。

统计口径与限制：

- 错误来自现有上游/账号认证日志，包含重试后恢复的失败。每个请求、账号去重；同一账号有失败的请求不再重复计为干净成功。
- 排除用户侧错误、count_tokens 错误和无 Token/费用/图片的失败占位用量；0 倍率但实际有输出的成功请求仍参与统计。
- 失败率分母至少为 5，减轻极少样本的波动。没有成功延迟样本时不会优先于有质量样本的账号；所有候选都无样本时，按已知失败情况、优先开关、倍率和原优先级兜底。
- 统计缓存 30 秒，查询最多等待 2 秒。统计缺失或失败时无法证明质量，回退到倍率与优先级。
- 日常请求不会主动探测所有渠道，也不保证实时全局最优。默认保持绑定，价格或速度变化本身不会触发频繁切换；管理员可通过“更新调度”主动评测所选模型。
